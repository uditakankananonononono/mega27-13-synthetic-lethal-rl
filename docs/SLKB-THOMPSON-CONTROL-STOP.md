# Curated count recovery: baseline mismatch, no model run

The approved archive retrieval yielded `SQL_Dumps.zip`, 240,825,452 bytes, SHA-256 05ece8a60b58916fcfb576be1b5a824773b42471f21e2c6b141b81de7da72576. It contains full SQLite and MySQL SQL dumps, totaling about 1.66 GB uncompressed, and small schemas. Source: https://ndownloader.figshare.com/files/41055392 ; provider metadata: https://api.figshare.com/v2/articles/22902839 (GPL 3.0+). No raw dump is redistributed in the repository.

Only three tables' rows for PubMed study 33637726 were streamed into a local selective database: 13,310 guide identities, 125,514 guide-pair count rows and 3,573 original result rows. There are 41,838 count rows per line, A375, MEWO and RPE1, and no unmatched guide IDs. The initial author-name scan returned zero because study identifiers are PubMed IDs; this was a query mismatch, not absence of data.

The curated T0 count vectors carry D14 replicate labels; TEnd vectors carry D28 labels. Primary Thompson screening used Cas9-negative A375 D7 as the baseline (https://www.nature.com/articles/s41467-021-21478-9). Thus this database cannot reproduce the primary baseline or the 2025 benchmark's specified input as-is. Integer-valued floats in curated counts are not proof that original processing/read pairing has been recovered. The database's A_B/B_A labels follow canonical gene orientation and cannot establish that promoters were physically swapped in the source design, which the primary paper describes as asymmetric.

The audit checks count-vector lengths, finite/nonnegative/integer values, replicate labels and guide foreign-key completeness. `results/slkb-thompson-control-audit.json` records the result. No fit, candidate ranking or benchmark was launched. Proceed only after recovering true day7 input or freezing a separately labeled D14-to-D28 follow-on depletion estimand. Neither a different time interval nor a melanoma/retinal pair screen closes the HGSOC selective-lethality gate.
