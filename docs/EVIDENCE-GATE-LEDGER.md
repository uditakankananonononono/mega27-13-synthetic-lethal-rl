# Evidence gate ledger (not a result upgrade)

Run `python3 scripts/evidence_gate_ledger.py --output results/evidence-gate-ledger.json` to regenerate the machine-readable ledger from six committed result artifacts. Their SHA-256 values are included in the output, and the generator fails if the assay's 455 assessed triples, its zero BH q<0.05, the zero-shift position-layout sign, the ten proxy seeds, or the development-only identity/source conditions change without an explicit review. `python3 -m unittest discover -s tests -q` runs the ledger test with the rest of the suite.

The current source assay is https://ftp.ncbi.nlm.nih.gov/geo/series/GSE154nnn/GSE154112/suppl/ (workbook hash recorded in `results/gse154112-exploratory-contrasts.json`). The PEO1 QC stop concerns https://ftp.ncbi.nlm.nih.gov/geo/series/GSE123nnn/GSE123290/suppl/ . The Project SCORE historical monogenic matrix comes from https://figshare.com/articles/dataset/Project_SCORE_processed_with_CERES/9116732/1 . Source URLs show provenance, not proof of healthy viability or independent multi-HGSOC pair/triple outcomes.

The ledger explicitly marks every remaining major completion gate UNMET, including external measured benchmark beat, new discovery, matched normal viability, 120 datasets, 40 externally executed tools, ten implemented judge rounds and the 50+ substantive-text-body-page paper. It does not infer these gates from missing files. Its current `UNMET` declarations reflect the audited project state and must be independently updated when new evidence exists. In particular, the proxy's greedy/beam 10/10 wins are **against** RL on a circular surrogate, not a fair external biology benchmark; the PEO1 guide-count table is not a usable hit list until source-specific QC resolves; engineering tests are not biological validation. No 'pass' button is provided by the generator.
